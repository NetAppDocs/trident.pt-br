= Crie uma função do IAM e um segredo do AWS Secrets Manager
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Você pode configurar pods do Kubernetes para acessar recursos da AWS autenticando como uma função do AWS IAM em vez de fornecer credenciais explícitas da AWS.


NOTE: Para autenticar usando uma função do IAM da AWS, você precisa ter um cluster Kubernetes implantado usando o Amazon EKS ou o Red Hat OpenShift.



[[create-an-aws-secrets-manager-secret]]
== Crie um segredo do AWS Secrets Manager

O Trident precisa de credenciais para gerenciar o armazenamento na SVM do FSx for ONTAP. Armazene as `vsadmin` credenciais em um segredo do AWS Secrets Manager.

Este exemplo cria um segredo do AWS Secrets Manager para armazenar credenciais do Trident CSI:

[source, console]
----
aws secretsmanager create-secret --name trident-secret --description "Trident CSI credentials" \
  --secret-string "{\"username\":\"vsadmin\",\"password\":\"<svm_password>\"}"
----


[[create-an-iam-policy]]
== Crie uma política IAM

O Trident também precisa de permissões da AWS para ser executado corretamente. Portanto, você precisa criar uma política que dê ao Trident as permissões de que ele precisa.

O exemplo a seguir cria uma política do IAM usando a AWS CLI:

[source, console]
----
aws iam create-policy --policy-name AmazonFSxNCSIDriverPolicy --policy-document file://policy.json \
  --description "This policy grants Trident CSI access to FSx for ONTAP and AWS Secrets Manager" \
  --query Policy.Arn --output text
----
O comando retorna o ARN da política. Use-o nos comandos a seguir.

* Exemplo JSON de política*:

[source, json]
----
{
  "Statement": [
    {
      "Action": [
        "fsx:DescribeFileSystems",
        "fsx:DescribeVolumes",
        "fsx:CreateVolume",
        "fsx:RestoreVolumeFromSnapshot",
        "fsx:DescribeStorageVirtualMachines",
        "fsx:UntagResource",
        "fsx:UpdateVolume",
        "fsx:TagResource",
        "fsx:DeleteVolume"
      ],
      "Effect": "Allow",
      "Resource": "*"
    },
    {
      "Action": "secretsmanager:GetSecretValue",
      "Effect": "Allow",
      "Resource": "arn:aws:secretsmanager:<aws-region>:<aws-account-id>:secret:<aws-secret-manager-name>*"
    }
  ],
  "Version": "2012-10-17"
}
----


[[create-an-iam-role-for-pod-identity-or-an-iam-role-for-a-service-account-irsa]]
=== Crie uma função IAM para Pod Identity ou uma função IAM para uma conta de serviço (IRSA)

Você pode configurar uma conta de serviço do Kubernetes para assumir uma função do AWS Identity and Access Management (IAM) com o EKS Pod Identity ou funções do IAM para contas de serviço (IRSA). Os pods configurados para usar a conta de serviço podem então acessar os serviços da AWS aos quais a função tem permissão de acesso.

[role="tabbed-block"]
====
.Identidade do Pod (EKS)
--
As associações de identidade do Amazon EKS Pod fornecem a capacidade de gerenciar credenciais para seus aplicativos, de forma semelhante à maneira como os perfis de instância do Amazon EC2 fornecem credenciais para instâncias do Amazon EC2.

*Instale o Pod Identity no seu cluster EKS*:

Você pode criar uma identidade de Pod por meio do console da AWS ou usando o seguinte comando da AWS CLI:

[listing]
----
aws eks create-addon --cluster-name <EKS_CLUSTER_NAME> --addon-name eks-pod-identity-agent
----
Para obter mais informações, consulte link:https://docs.aws.amazon.com/eks/latest/userguide/pod-id-agent-setup.html["Configurar o agente de identidade do pod do Amazon EKS"].

*Crie trust-relationship.json*:

Crie trust-relationship.json para permitir que o EKS Service Principal assuma essa função para a Identidade do Pod. Em seguida, crie uma função com esta política de confiança:

[listing]
----
aws iam create-role \
  --role-name fsxn-csi-role --assume-role-policy-document file://trust-relationship.json \
  --description "fsxn csi pod identity role"
----
*arquivo trust-relationship.json*:

[source, json]
----

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Service": "pods.eks.amazonaws.com"
      },
      "Action": [
        "sts:AssumeRole",
        "sts:TagSession"
      ]
    }
  ]
}
----
*Anexe a política de função à função do IAM*:

Anexe a política de função da etapa anterior à função do IAM que foi criada:

[listing]
----
aws iam attach-role-policy \
  --policy-arn arn:aws:iam::aws:111122223333:policy/fsxn-csi-policy \
  --role-name fsxn-csi-role
----
*Crie uma associação de identidade de pod*:

Crie uma associação de identidade de pod entre a função IAM e a conta de serviço do Trident (`trident-controller`).

[listing]
----
aws eks create-pod-identity-association \
  --cluster-name <EKS_CLUSTER_NAME> \
  --role-arn arn:aws:iam::111122223333:role/fsxn-csi-role \
  --namespace trident --service-account trident-controller
----
--
.Função do IAM para contas de serviço (IRSA) (somente no EKS)
--
*Usando a AWS CLI*:

[listing]
----
aws iam create-role --role-name AmazonEKS_FSxN_CSI_DriverRole \
  --assume-role-policy-document file://trust-relationship.json
----
* arquivo trust-relation.json:*

[source, json]
----
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::<account_id>:oidc-provider/<oidc_provider>"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "<oidc_provider>:aud": "sts.amazonaws.com",
          "<oidc_provider>:sub": "system:serviceaccount:trident:trident-controller"
        }
      }
    }
  ]
}
----
Atualize os seguintes valores no `trust-relationship.json` arquivo:

* *<account_id>* - Seu ID de conta da AWS
* *<oidc_provider>* - A URL do provedor OIDC para o seu cluster EKS. Você pode obtê-la executando:
+
[source, console]
----
aws eks describe-cluster --name my-cluster --query "cluster.identity.oidc.issuer" \
  --output text | sed -e "s/^https:\/\///"
----


*Anexe a política do IAM à função do IAM*:

Depois que a função tiver sido criada, anexe a política (que foi criada na etapa acima) à função usando este comando:

[source, console]
----
aws iam attach-role-policy --role-name my-role --policy-arn <IAM policy ARN>
----
*Verifique a associação do provedor OIDC*:

Verifique se o seu provedor OIDC está associado ao seu cluster ao executar este comando:

[source, console]
----
aws iam list-open-id-connect-providers | grep $oidc_id | cut -d "/" -f4
----
Se a saída estiver vazia, use o seguinte comando para associar o IAM OIDC ao cluster:

[source, console]
----
eksctl utils associate-iam-oidc-provider --cluster $cluster_name --approve
----
Se você estiver usando `eksctl`, use o exemplo a seguir para criar uma função do IAM para uma conta de serviço no EKS:

[source, console]
----
eksctl create iamserviceaccount --name trident-controller --namespace trident \
  --cluster <my-cluster> --role-name AmazonEKS_FSxN_CSI_DriverRole --role-only \
  --attach-policy-arn <IAM-Policy ARN> --approve
----
--
.Função do IAM para o OpenShift autogerenciado
--
A implantação autogerenciada do OpenShift cria funções do IAM e as associa aos nós do cluster. Anexe a política do IAM do Trident à função atribuída a cada nó.

Para encontrar os IDs das instâncias dos nós em seu cluster, execute o seguinte comando:

[source, console]
----
oc get nodes -o jsonpath='{range .items[*]}{.spec.providerID}{"\n"}{end}'
----
Para encontrar a função do IAM associada a cada instância, execute o seguinte comando para cada instância:

[source, console]
----
aws ec2 describe-instances --instance-ids <instance-id> --query 'Reservations[*].Instances[*].IamInstanceProfile.Arn' --output text
----
Anexe a política do IAM a cada função executando o seguinte comando:

[source, console]
----
aws iam attach-role-policy --role-name <role-name> --policy-arn <IAM policy ARN>
----
